### Junction Bridge Fix (v33.1.4):
**Root cause:** Photo waypoints for adjacent paths don't connect — pixel gaps of 27-131px between path endpoints. When carts transition between paths, they either disappear (clamped to path boundary), jump (blend ends), or bunch up (stack at boundary).

**Fix:** Added `JUNCTION_BRIDGES` table in `track_photo.py` with intermediate pixel points for each path transition gap. `PhotoTrackModel.transition_path()` walks through bridge points. `CartAnimator` now stores `px_blend_from_path` and uses `transition_path()` during blends. Blend duration scales with gap size (0.3s small, 0.8s large).

Key gaps bridged:
- Path 1→3: 69px gap (right junction, Mold 1 side)
- Path 3→5: 132px gap (left junction, Mold 2 entry)
- Path 4→6: 108px gap (left junction, Mold 2 exit)
- Path 6→2: 27px gap (right junction, Mold 1 entry)

### v33.1.5 — Destination-driven animation (built & pushed)
**Complete rewrite of cart animation approach.** Replaced dead-reckoning from raw PLC positions with destination-driven route planning. Each cart now:
1. Plans a route from its current (path, pos) to its destination station using the path topology (6->1/2->3->4/5->6 loop)
2. Animates along that route at a steady speed (0.4 m/s default, or PLC-reported velocity if available)
3. Never stops until it arrives at destination or a fault occurs
4. Re-plans from the true position when a PLC poll diverges from prediction by >0.15m

Key new components:
- `_STATION_PATH` lookup: station_id -> (path, position)
- `_next_path()`: path junction routing based on destination
- `_plan_route()`: computes full path sequence from any position to any destination
- `CartAnimator` rewritten: route-based animation instead of dead-reckoning
- Junction bridges still used for pixel-space path transitions

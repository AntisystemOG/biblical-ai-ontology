## PLCTool I/O Status Fix - Complete Debug Transcript

### Problem Summary
Both logical names and physical addresses were failing with "Tag doesn't exist" error. The PLC was responding but rejecting tag names.

### Root Cause Discovery Process

#### Step 1: Added "Enumerate PLC Tags" Feature
Created a diagnostics button that uses pycomm3 to list every tag on the controller to see what format the PLC actually exposes.

**Result:** `get_tag_list()` found **271 tags** on the Micro870:
- Tags like `USER_BIT_1` through `USER_BIT_45` (and 231 more)
- Format probe tested 8 different name variants

#### Step 2: Format Probe Results
```
_IO_EM_DI_00 OK → True [BOOL]
_IO_EM_DI_0 ERR: None
_IO_EM_IN_00 ERR: None
_IO_EM_IN_0 ERR: None
_IOEM_DI_00 ERR: None
IO_EM_DI_00 ERR: None
_IO_P1_DI_00 ERR: None
_IO_X1_DI_00 OK → False [BOOL]
```

**Key Finding:** 
- `_IO_EM_DI_00` → OK ✓
- `_IO_X1_DI_00` → OK ✓

The CSV physical addresses were correct all along.

#### Step 3: The Real Fix
The reason the probe worked but earlier reads failed: **LogixDriver.read() requires its internal tag-type cache to be populated first.**

After `get_tag_list()` ran, pycomm3 knew the data types and reads worked. The fix was one line: call `get_tag_list()` during connect so the cache is ready before any reads happen.

#### Step 4: The Silent Timer Bug
After getting reads working via Quick Scan, the I/O Status tab still wasn't updating live.

**Found:** `TagMonitorTab` was missing the `poll_interval_ms` property. `main_window.py` referenced it but it didn't exist. This caused:
1. `_update_ui_connected()` threw an `AttributeError`
2. Qt's signal dispatch swallowed the exception silently
3. The poll timer never started
4. `_poll_tick()` was never called automatically

Everything that worked (diagnostics, quick scan) was manual button presses that bypassed the timer.

**Fix:** Added the `poll_interval_ms` property to `TagMonitorTab`.

### Final State
- 5/5 CSV tags reading successfully
- Live I/O Status tab updating every 1000ms
- Status bar shows "Polling OK — X reads succeeded"

## Key Lesson
The timer being dead made everything look like a communication problem when it was actually just a missing property that killed the entire connect flow silently. Qt's exception swallowing in slots is dangerous — always check for AttributeError in UI update code.

# Electron App Clone Recipe: Reverse-Engineer + Rebuild

## When to Use This

User says: "clone this desktop app," "make it look exactly like X," or "build a local version of Y." This is a validated workflow for taking a real packaged Electron app, extracting its design system, and rebuilding a clone with a different backend.

## The Claude Desktop → Spock Code Case Study

This recipe is validated against cloning the real **Claude Desktop** app (Anthropic, Windows MSIX package) into **Spock Code** (Ollama-powered local clone).

---

## Phase 1: Locate and Extract the Original

### Step 1: Find the Install Path

**Windows MSIX/APPX apps** live in `C:\Program Files\WindowsApps\`. Use PowerShell:

```powershell
Get-AppxPackage | Where-Object { $_.Name -like "*Claude*" }
```

Output:
```
Name              : Anthropic.Claude
PackageFullName   : Anthropic.Claude_1.8089.1.0_x64__pzs8sxrjxfjjc
InstallLocation   : C:\Program Files\WindowsApps\Anthropic.Claude_1.8089.1.0_x64__pzs8sxrjxfjjc
```

### Step 2: Copy app.asar Out

The `WindowsApps` directory is ACL-protected. Copy the ASAR to a writable location:

```powershell
Copy-Item "C:\Program Files\WindowsApps\Anthropic.Claude_1.8089.1.0_x64__pzs8sxrjxfjjc\app\app.asar" "C:\Users\thadd\claude-app.asar"
```

### Step 3: Extract with asar

```bash
npm install -g asar
npx asar extract claude-app.asar ./claude-src/
```

**What to read first:**
| File | What It Contains |
|------|-----------------|
| `claude-src/.vite/renderer/main_window/window-shared.css` | CSS custom properties, HSL color values, font stacks |
| `claude-src/dist/assets/index-*.css` | Tailwind-generated utilities (search for class names) |
| `claude-src/package.json` | Electron version (31.7.7), Tailwind version, React version |
| `claude-src/tailwind.config.*` | Extended palette names: `clay`, `paper`, `ink`, `surface` |
| `claude-src/dist/assets/index-*.js` | Minified but searchable for component class strings |

## Phase 4: The Tailwind Pre-Build Workaround

This is **critical** — Vite's PostCSS pipeline does not reliably run Tailwind in Electron projects.

### Step 1: Configure tailwind.config.js

```js
module.exports = {
  content: ['./src/**/*.{js,ts,jsx,tsx}', './index.html'],
  theme: {
    extend: {
      colors: {
        surface: '#12120f',
        background: '#1a1914',
        'text-100': '#f5f4ef',
        'text-200': '#b8b4a8',
        clay: { 100: '#d97757', 200: '#c26a4d', 300: '#a85d44' },
        paper: { 50: '#f5f4ef', 100: '#e8e6df', 200: '#d1cfc7' },
        ink: { 50: '#8a8780', 100: '#6c6a60', 200: '#4f4d45' },
      },
      fontFamily: {
        sans: ['-apple-system','BlinkMacSystemFont','"Segoe UI"','Roboto','sans-serif'],
      },
    },
  },
  plugins: [],
}
```

### Step 2: Pre-build CSS

```bash
npx tailwindcss -i ./src/styles/global.css -o ./src/styles/tailwind-build.css --minify
```

### Step 3: Import pre-built in main.tsx

```tsx
import './styles/tailwind-build.css'  // NOT './styles/global.css'
```

See `references/electron-tailwind-vite-workaround.md` for full details.

## Phase 6: Swap the Backend to Ollama

### Preload API (preload.ts)

```ts
import { contextBridge, ipcRenderer } from 'electron'

contextBridge.exposeInMainWorld('spockAPI', {
  ollamaChat: (messages: any[], model: string) =>
    ipcRenderer.invoke('ollama-chat', messages, model),
  listModels: () => ipcRenderer.invoke('ollama-list'),
  selectFolder: () => ipcRenderer.invoke('select-folder'),
  readFile: (path: string) => ipcRenderer.invoke('read-file', path),
  writeFile: (path: string, content: string) => ipcRenderer.invoke('write-file', path, content),
  runCommand: (cmd: string, cwd?: string) => ipcRenderer.invoke('run-command', cmd, cwd),
})
```

### Main Process IPC (main.ts)

```ts
ipcMain.handle('ollama-chat', async (event, messages, model) => {
  const response = await fetch('http://127.0.0.1:11434/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ model, messages, stream: true }),
  })
  return response.body  // Return the stream for renderer processing
})

ipcMain.handle('ollama-list', async () => {
  const res = await fetch('http://127.0.0.1:11434/api/tags')
  const data = await res.json()
  return data.models.map((m: any) => m.name)
})
```

### Renderer Streaming (ChatView.tsx)

```ts
const streamResponse = async (messages: any[], model: string) => {
  const response = await window.spockAPI.ollamaChat(messages, model)
  const reader = response.getReader()
  const decoder = new TextDecoder()
  let text = ''

  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    text += decoder.decode(value, { stream: true })
    // Parse JSON lines: {"message":{"content":"..."}}
    const lines = text.split('\n').filter(l => l.trim())
    for (const line of lines) {
      try {
        const json = JSON.parse(line)
        if (json.message?.content) {
          appendToMessage(json.message.content)
        }
      } catch {}
    }
  }
}
```

## Phase 7: Build and Package

### The "Not Even Close" Visual Failure Mode

After following all phases above, the app may still look nothing like the original. If the user says **"wow not even close"**, check these in order:

1. **CSS bundle size** — `dist/assets/index-*.css` must be > 10 kB. If < 1 kB, Tailwind utilities were never generated. Fix: ensure `@tailwind` directives are in `global.css`, pre-build via CLI, and import `tailwind-build.css` in `main.tsx`.
2. **CSS custom property scope** — The `index.html` inline `<style>` block must define all `var(--*)` properties used by components. If `var(--claude-fg)` is undefined, text renders as default/invisible. Fix: define `:root` variables in BOTH `index.html` `<style>` and `global.css`.
3. **Hardcoded legacy colors in index.html** — An old `<style>` block with `background:#0f0f10; color:#ececf1` will override all CSS variables. Fix: remove hardcoded colors, use `var(--claude-bg)` and `var(--claude-fg)`.
4. **Old CSS still cached** — The previous broken build's `dist/` may have stale `index.html` or CSS. Fix: `NODE_ENV=production npx vite build --emptyOutDir` (note `--emptyOutDir`).

See `references/electron-tailwind-vite-workaround.md` for the full CSS scope fix.

### Build Steps

```bash
# 1. Pre-build Tailwind
npx tailwindcss -i ./src/styles/global.css -o ./src/styles/tailwind-build.css --minify

# 2. Build renderer (Vite)
NODE_ENV=production npx vite build --emptyOutDir

# 3. Build Electron main + preload
npx tsc --project tsconfig.electron.json

# 4. Package for Windows (no signing, no NSIS)
npx electron-builder --win dir
```

### Electron Builder Config (package.json build field)

```json
{
  "build": {
    "appId": "com.spock.code",
    "productName": "Spock Code",
    "directories": {
      "output": "release"
    },
    "files": [
      "dist/**/*",
      "dist-electron/**/*",
      "resources/**/*"
    ],
    "win": {
      "target": "dir",
      "signingHashAlgorithms": [],
      "signAndEditExecutable": false,
      "icon": "resources/icon.ico"
    }
  }
}
```

**Why `dir` target:**
- Avoids NSIS (no `makensis` needed on WSL)
- Avoids code signing (no `wine` needed)
- Produces `release/win-unpacked/Spock Code.exe` directly
- Create a `.lnk` shortcut afterward for the desktop

## Key Differences from Original

The ONLY intentional differences in the clone:
1. **Backend:** Ollama local API instead of Claude API
2. **Product name:** "Spock Code" instead of "Claude"
3. **Icon/branding:** Custom icon instead of Anthropic logo
4. **Font:** System sans-serif instead of AnthropicSans (unavailable)

Everything else — layout, colors, spacing, component structure — should match the original pixel-for-pixel.
